## 1. Introduction

The Radxa ZERO 3W is built around the **Rockchip RK3566** SoC (System on Chip).
Besides four Cortex-A55 CPUs you already met conceptually in Phase 1, the silicon
(and the board around it) includes:

- A **PMIC** (external power chip) feeding many voltage rails  
- A **clock tree** (crystal → PLLs → CRU)  
- **UART**, **GPIO**, **USB**, **DDR**, **eMMC**/SD controllers  

This lesson walks those blocks using **public** Radxa schematics and Rockchip /
Linux documentation. We cite sources instead of inventing register folklore —
important because much of the full TRM is NDA-gated (PRD risk R2).

## 2. Definitions

| Term | Meaning |
|---|---|
| **SoC** | System on Chip — CPU cores + peripherals on one die. |
| **PMIC** | Power Management IC — external chip (on ZERO 3W: **RK817-5**) that creates 0.9 V / 1.8 V / 3.3 V / DDR rails from 5 V. |
| **PMU** | On-chip Power Management Unit inside RK3566 (domains like VD_LOGIC). Different from the external PMIC. |
| **CRU** | Clock and Reset Unit — enables and divides clocks, asserts resets to blocks. |
| **PMUCRU** | Clock controller for the PMU / always-on domains. |
| **MMIO** | Memory-Mapped I/O — programming hardware by reading/writing special physical addresses. |
| **UART** | Universal Asynchronous Receiver/Transmitter — serial port. Debug console = UART2 on ZERO 3W. |
| **GPIO** | General-Purpose Input/Output — digital pins; often muxed with UART/I2C/SPI. |
| **Pinmux** | Pin multiplexing — choosing which function a ball/pin carries. |
| **DDR / LPDDR4** | Board DRAM technology (Low-Power DDR4). |
| **eMMC** | Embedded MMC flash soldered on the board (optional on ZERO 3W). |
| **PHY** | Physical layer transceiver (e.g. USB PHY) between controller and connector. |
| **Boot ROM** | Immutable code in the SoC that runs first and can load the next stage from SD/eMMC/USB. |
| **DT / dtsi** | Device Tree — Linux’s description of hardware addresses and wiring. |

## 3. Architecture

Two layers matter:

1. **SoC internals** — CPU, CRU, PMU, UART, GPIO, DDR ctrl, eMMC, USB PHYs  
2. **Board wiring** — RK817 PMIC, LPDDR4 package, eMMC, Type-C ports, 40-pin header, 24 MHz crystal  

```
5V ──▶ RK817 PMIC ──rails──▶ RK3566 ──▶ LPDDR4
                     ▲          │
                     │ I2C0     ├── UART2 ──▶ pins 8/10 (debug)
                24 MHz XTAL     ├── GPIO  ──▶ 40-pin header
                                ├── USB   ──▶ Type-C
                                └── eMMC/SD
```

Full diagrams: [`block-diagram.md`](../hardware/block-diagram.md).

## 4. Internal Workflow

### Power-on (conceptual)

1. Apply 5 V [S5].  
2. RK817 starts, raises `VDD_LOGIC`, `VCC_DDR`, 3.3 V, … [S1].  
3. 24 MHz oscillator runs; CRU/PLLs come up [S6][S8].  
4. Boot ROM executes, looks for a boot medium (SD / eMMC / USB) [S6].  
5. Later stages (SPL/U-Boot — Phase 3–4) print on **UART2 @ 1.5 Mbaud** [S4].

### Talking to a peripheral (MMIO)

```
CPU issues load/store to physical address 0xfe660000…
        │
        ▼
   UART2 hardware registers
        │
        ▼
   TX pin toggles → USB-TTL → your terminal
```

You rarely poke these by hand in AstraOS; U-Boot and Linux drivers do. Knowing
the **base address** still matters when reading DT, crash logs, and TRM
excerpts.

### Clocks before use

Almost every block needs:

1. A clock enabled in **CRU** / **PMUCRU**  
2. Correct **pinmux**  
3. Driver programming  

Missing step 1 → silent peripheral. Missing step 2 → signal on the wrong pin.

## 10. Troubleshooting & Common Pitfalls

### “I can’t find the TRM PDF Rockchip uses internally”

```
(no public download / NDA wall)
```

**Cause:** PRD risk R2 — documentation partially closed.  
**Fix:** Use [S1][S6][S7][S9]. Do not invent register layouts. Flag gaps in notes
§10.

### Wrong UART pins → no boot log later

```
(terminal stays blank at Phase 3)
```

**Cause:** Swapped TX/RX, wrong GND, or baud not 1500000.  
**Fix:** Re-read [S4]; adapter RX↔board TX (pin 8), adapter TX↔board RX (pin 10).

### Assuming PMIC == PMU

**Pitfall:** Using the words interchangeably.  
**Reality:** **PMIC** = external RK817. **PMU** = on-chip domain controller [S6].
Both appear in logs/schematics.

### Poking random MMIO from userspace “to learn”

```
Bus error / instant reboot / silent hang
```

**Cause:** Wrong address, clock gated, or secure/firewall.  
**Fix:** Phase 2 is read-the-map only. Program peripherals via U-Boot/Linux
later.

### Schematic revision mismatch

**Pitfall:** Notes written against v1.11 while your board PDF is older.  
**Fix:** Always download the schematic revision matching your silkscreen /
Radxa docs; re-check sheet 21 for PMIC marking.

### eMMC vs microSD confusion

**Pitfall:** “The board has no storage” on a SKU without eMMC.  
**Reality:** microSD is always there; eMMC is optional [S2][S5]. Boot ROM can
use either [S6].

### Using `0xfd7c0000` for CRU from a random blog

**Pitfall:** Stale or SoC-confused addresses.  
**Fix:** Trust [S9] `cru@fdd20000` for this family unless a cited TRM says
otherwise.

## 11. Summary

- ZERO 3W = RK3566 + RK817 PMIC + LPDDR4 + USB-C + optional eMMC + microSD.  
- Clocks start from a **24 MHz** crystal and fan out through **CRU/PMUCRU**.  
- Your debug lifeline is **UART2** on pins 8/10 at **1.5 Mbaud**.  
- Learner register map = public DT bases, cited — not a fake full TRM.
